# คู่มือการป้องกันและรักษาความปลอดภัยแอป Android (Advanced Protection Guide)

สำหรับโปรเจค **MCF-ZXD44** เพื่อป้องกันการแกะโค้ด (Reverse Engineering) และการแก้ไขแอป (Modding/Cracking)

---

## 1. การป้องกันระดับซอร์สโค้ด (Code Obfuscation)
วิธีนี้คือการเปลี่ยนชื่อ คลาส, ฟังก์ชัน และตัวแปร จากชื่อที่อ่านออก (เช่น `isDeviceAuthorized`) ให้กลายเป็นตัวอักษรที่ไม่มีความหมาย (เช่น `a`, `b`, `c`)

### วิธีตั้งค่าใน Android Studio:
ไปที่ไฟล์ `app/build.gradle` (Module level) และแก้ไขในส่วน `buildTypes`:

```gradle
android {
    ...
    buildTypes {
        release {
            // เปิดใช้งานการย่อโค้ดและป้องกันการแกะ
            minifyEnabled true
            // ลบทรัพยากรที่ไม่ได้ใช้เพื่อลดขนาดแอป
            shrinkResources true
            // ใช้ไฟล์กฎเริ่มต้นของโปรเกลาต์
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

> [!IMPORTANT]
> หลังจากเปิด `minifyEnabled true` แล้ว คุณต้องทดสอบรันแอปในโหมด Release เสมอ เพราะบางครั้งการเปลี่ยนชื่อโค้ดอาจทำให้บางฟังก์ชัน (เช่น ML Kit หรือ Gson) ทำงานผิดพลาด ต้องไปเพิ่มข้อยกเว้นในไฟล์ `proguard-rules.pro`

## 2. การป้องกันข้อมูลสำคัญ (String & API Key Protection)
อย่าเก็บคีย์สำคัญ หรือ URL ของเซิร์ฟเวอร์ไว้ในรูปแบบ String ปกติ เพราะสามารถถูกค้นหาเจอได้ง่ายเหมือนที่ผมพิสูจน์ให้ดู

### วิธีแก้ไข:
*   **ใช้ C++ (NDK):** เก็บข้อมูลสำคัญไว้ในไฟล์ `.so` (C++) จะแกะยากกว่า Java/Kotlin มาก
*   **ใช้รหัสลับ (XOR Encryption):** อย่าเก็บ String ตรงๆ ให้เก็บเป็นค่าที่เข้ารหัสไว้ แล้วค่อยถอดรหัสในขณะรันแอป

## 3. การตรวจสอบความถูกต้องของแอป (Integrity & Signature Check)
เพื่อป้องกันไม่ให้คนอื่นแก้ไขแอปแล้วนำไป "Re-sign" (เซ็นชื่อใหม่) เพื่อใช้งาน

### โค้ดแนะนำสำหรับเช็ค Signature:
ควรมีฟังก์ชันที่เช็ค SHA-256 ของใบเซอร์แอปคุณเอง และถ้าไม่ตรงให้สั่งปิดแอปทันที

```kotlin
fun verifySignature(context: Context): Boolean {
    val mySignatureHash = "YOUR_APP_SIGNATURE_SHA256_HERE"
    // ดึงค่า Signature จากเครื่องที่รันอยู่มาเทียบ
    // ถ้าไม่ตรงกัน แสดงว่าแอปถูกแก้
    return currentHash == mySignatureHash
}
```

## 4. การตรวจสอบการ Debug และ Emulator
ป้องกันนักแคร็กที่ใช้โปรแกรม Debug หรือรันบนคอมพิวเตอร์เพื่อแกะการทำงาน

### สิ่งที่ควรเช็ค:
*   **Check Debugger:** `android.os.Debug.isDebuggerConnected()`
*   **Check Root:** ตรวจสอบไฟล์ระบบว่าเครื่องถูก Root หรือไม่ (ใช้ Library เช่น RootBeer)
*   **Check Emulator:** ตรวจสอบชื่อรุ่นมือถือ ถ้าเป็น "google_sdk" หรือ "vbox86" ให้สงสัยว่าเป็น Emulator

## 5. ย้ายการตัดสินใจไปที่ Server (Server-Side Validation)
**นี่คือวิธีที่ปลอดภัยที่สุด** อย่าตัดสินใจในแอปเพียงอย่างเดียวว่า "เครื่องนี้ผ่านหรือไม่"

*   **วิธีที่ผิด:** แอปถามเซิร์ฟเวอร์ -> เซิร์ฟเวอร์ตอบว่า OK -> แอปยอมให้ใช้งาน (แฮ็กเกอร์สามารถแก้แอปให้ข้ามขั้นตอนนี้ได้)
*   **วิธีที่ถูก:** แอปส่งข้อมูล -> เซิร์ฟเวอร์ตรวจสอบ -> เซิร์ฟเวอร์ส่ง "กุญแจสำคัญ" ที่ใช้รันบอทกลับมา (ถ้าไม่มีกุญแจนี้ บอทจะทำงานไม่ได้เลย แม้จะแก้โค้ดในแอปแล้วก็ตาม)

---

## 6. การใช้ตัวล็อคแอปชั้นนอก (Third-party Packers)
หากต้องการความปลอดภัยระดับสูงสุด สามารถใช้บริการ Packer เพื่อเข้ารหัส APK ทั้งไฟล์:
*   **Bangcle (เรียกอีกชื่อว่า SecShell)**
*   **Jiagu (360)**
*   **Tencent Legu**
วิธีเหล่านี้จะทำให้แม้แต่ผมก็ไม่สามารถเห็นไฟล์ `classes.dex` ข้างในได้เลยจนกว่าจะทำการ "Unpack" ซึ่งยากกว่าปกติหลายเท่าครับ

---

> [!TIP]
> **คำแนะนำสุดท้าย:** ไม่มีการป้องกันใดที่ 100% แต่วัตถุประสงค์ของเราคือการทำให้ "ต้นทุนในการแฮ็ก" สูงกว่า "ค่าบริการบอท" จนแฮ็กเกอร์รู้สึกไม่คุ้มที่จะทำครับ
